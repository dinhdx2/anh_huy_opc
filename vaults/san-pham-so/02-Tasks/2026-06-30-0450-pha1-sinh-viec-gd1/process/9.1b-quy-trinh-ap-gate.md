# 9.1b — Quy Trình Áp Cổng Bản Quyền Trước Mỗi Lần Phát Hành

> **TL;DR:** Trước MỖI lần phát hành (ra mắt mới, cập nhật file, thêm SKU), người tạo chạy checklist 9.1a, điền log, lưu bằng chứng. Fail → DỪNG hoàn toàn, không phát hành dù áp lực thời gian. Cổng này do CEO/founder tự thực hiện ở GĐ1.

---

## 1. Khi nào áp cổng?

| Sự kiện | Áp cổng? | Ghi chú |
|---|---|---|
| Ra mắt sản phẩm mới lần đầu | **BẮT BUỘC** | Chạy đầy đủ 5 cổng |
| Cập nhật file sản phẩm (thêm trang, sửa nội dung) | **BẮT BUỘC** | Chạy lại cổng liên quan đến phần thay đổi + tổng kết |
| Thêm asset mới (ảnh, icon, font) vào file có sẵn | **BẮT BUỘC** | Tối thiểu chạy Cổng 3 + 4 |
| Đổi hình thức giao hàng (từ file → Canva link hoặc ngược lại) | **BẮT BUỘC** | Chạy lại Cổng 1 |
| Chạy lại ads cho sản phẩm cũ không thay file | Không cần | File đã qua gate, không đổi |
| Ra thêm SKU mới (bundle, phiên bản mới) | **BẮT BUỘC** | Coi là sản phẩm mới |

---

## 2. Ai thực hiện?

| Giai đoạn | Người thực hiện | Ghi chú |
|---|---|---|
| **GĐ1 (hiện tại)** — team 1 người | CEO/founder tự chạy | Ghi log ngay vào file |
| GĐ2+ — có thêm người tạo nội dung | Người tạo tự chạy + CEO review log | CEO ký duyệt log trước phát hành |
| Khi có freelancer làm asset | Freelancer nộp bằng chứng license + CEO kiểm | Hợp đồng freelancer phải ghi rõ trách nhiệm bản quyền |

---

## 3. Quy trình từng bước

```
BƯỚC 1 — Chuẩn bị (trước phát hành ≥ 1 ngày làm việc)
  └─ Lấy file sản phẩm phiên bản cuối (đã lock, không sửa nữa)
  └─ Mở checklist 9.1a
  └─ Chuẩn bị thư mục lưu bằng chứng: assets/license-proof/<tên-sp>/

BƯỚC 2 — Chạy Cổng 1 đến 5 (theo thứ tự)
  └─ Tick từng mục ☐ PASS hoặc ☐ FAIL
  └─ Chụp ảnh/lưu URL bằng chứng cho từng mục PASS
  └─ Nếu FAIL: ghi rõ lý do + hành động cần làm → DỪNG ngay, không chạy tiếp

BƯỚC 3 — Điền Gate Log (xem mục 4 bên dưới)
  └─ Điền vào bảng kết quả trong 9.1a
  └─ Điền vào Gate Log riêng (mục 4 file này)

BƯỚC 4 — Kết quả
  ├─ ALL PASS → được phép phát hành → thông báo cho bộ phận vận hành
  └─ CÓ FAIL → DỪNG phát hành → xử lý fail → quay lại Bước 1

BƯỚC 5 — Lưu trữ
  └─ Lưu log + bằng chứng vào thư mục license-proof
  └─ Commit/push lên git (bảo toàn bằng chứng)
```

---

## 4. Mẫu Gate Log (điền sau mỗi lần chạy cổng)

```markdown
## Gate Log — [Tên sản phẩm] — [Phiên bản]

| Trường | Nội dung |
|---|---|
| Ngày chạy cổng | YYYY-MM-DD |
| Người chạy | [Tên] |
| Tên sản phẩm | [ví dụ: Kit Lên Đơn Shopee v1.0] |
| Phiên bản file | [v1.0 / v2.1 / ...] |
| Hash/tên file cuối | [tên file chính xác, ví dụ: kit-len-don-v1.pdf] |
| Sự kiện kích hoạt | [Ra mắt mới / Cập nhật / Thêm asset / Đổi hình thức giao hàng] |

### Kết quả từng cổng
| Cổng | Tên | Kết quả | Ghi chú |
|---|---|---|---|
| 1 | Canva Pro Elements | ☐ PASS / ☐ FAIL / ☐ N/A | |
| 2 | Raw AI Output | ☐ PASS / ☐ FAIL / ☐ N/A | |
| 3 | Font chữ | ☐ PASS / ☐ FAIL / ☐ N/A | |
| 4 | Ảnh/Icon/Nhạc/Vector | ☐ PASS / ☐ FAIL / ☐ N/A | |
| 5 | Nội dung văn bản | ☐ PASS / ☐ FAIL / ☐ N/A | |

### Kết luận
- [ ] **ALL PASS → PHÁT HÀNH ĐƯỢC** (ký tên: ____________ · ngày: ________)
- [ ] **CÓ FAIL → DỪNG PHÁT HÀNH**

### Mục fail & hành động (nếu có)
| Mục fail | Lý do | Hành động | Deadline sửa |
|---|---|---|---|
| | | | |

### Thư mục bằng chứng
Lưu tại: `assets/license-proof/[tên-sp]-[version]/`
```

## 5. Xử lý khi FAIL

| Loại fail | Hành động | Thời gian xử lý ước tính |
|---|---|---|
| Có Canva Pro element trong file export | Xóa element đó → thay bằng Free element hoặc tự tạo → chạy lại gate | 2–4 giờ |
| Raw AI output chưa chỉnh sửa | Người tạo chỉnh sửa thực chất → chạy lại gate | 1–2 ngày |
| Font chưa rõ commercial license | Thay bằng Google Fonts (Be Vietnam Pro, Nunito, Roboto) → chạy lại | 2–4 giờ |
| Ảnh/icon không rõ nguồn | Xóa → thay bằng Unsplash/Pexels với commercial license rõ → chạy lại | 4–8 giờ |
| Nội dung sao chép quá gần nguồn khác | Viết lại → xin phép hoặc bỏ → chạy lại | 1–3 ngày |

**Nguyên tắc cứng: KHÔNG phát hành khi đang có mục fail, dù deadline ads đã đặt.**
